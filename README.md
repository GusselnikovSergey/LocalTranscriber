# LocalTranscriber — локальная транскрибация

Настольное приложение для Windows: превращает **аудио и видео в текст** и распознаёт **текст с изображений и PDF**. Всё выполняется на вашем компьютере — файлы никуда не отправляются. Интернет нужен только один раз, чтобы скачать модели.

## Что умеет

| Вход | Что получается |
|---|---|
| `mp3, wav, m4a, aac, ogg, opus, flac, wma` | текст с разбивкой на абзацы, экспорт `.txt`, `.srt`, `.vtt`, `.json` с таймкодами |
| `mp4, mkv, avi, mov, webm, mpg, ts, flv, 3gp` | то же самое: звук извлекается из видео автоматически |
| `png, jpg, jpeg, bmp, tif, tiff, webp` | текст в порядке строк (русский OCR) |
| `pdf` | готовый текстовый слой, если он есть; страницы-сканы распознаются OCR |

Основной язык — русский (можно включить автоопределение). Работает на CPU без видеокарты.

## Требования

- Windows 10/11 x64, Python 3.12+ (проверено на 3.14).
- Свободное место: ≈1,5 ГБ на зависимости и от 1 до 3 ГБ на модель речи.
- Внешние `ffmpeg` и `tesseract` **не нужны**.

## Установка и запуск

```powershell
cd "C:\Users\Сергей\Documents\Проект по умолчанию\projects\LocalTranscriber"
.\run.ps1
```

`run.ps1` при первом запуске создаст `.venv`, установит зависимости и откроет окно. Дальше запуск занимает секунды.

Вручную:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m localtranscriber
```

Версии зависимостей зафиксированы (`==`) по проверенному набору на Python 3.14.9. Для разработки
и проверок: `pip install -r requirements-dev.txt` (добавляет `pytest`, `ruff`, `mypy`).

## Первый запуск

При первом аудиофайле приложение скачает модель речи (`medium` по умолчанию, ≈1,5 ГБ) в
`%LOCALAPPDATA%\LocalTranscriber\models`. OCR-модель (≈20 МБ) скачается при первом изображении или скане.
Прогресс виден в нижней строке окна, загрузку можно отменить — при следующем запуске она
продолжится с того же места. После этого приложение работает без сети.

## Как пользоваться

1. Нажмите **«Добавить файлы»** или перетащите файлы в список (drag&drop).
2. Нажмите **«Обработать»**. Файлы обрабатываются по очереди, прогресс и статус — внизу окна.
   **«Отмена»** останавливает текущий прогон за доли секунды: файл помечается «Отменено», а необработанные
   файлы остаются в очереди — нажмите «Обработать» ещё раз, чтобы продолжить с них.
   Отмена работает и во время первой загрузки модели речи: начатая загрузка доводится до конца в фоне
   и переиспользуется при следующем запуске, поэтому повторно качать модель не придётся.
3. Выберите файл в списке — текст появится справа. Его можно править.
4. **«Копировать»** — в буфер обмена, **«Сохранить как…»** — в файл.

Каждый успешно обработанный файл автоматически сохраняется как `.txt` в папке результатов
(по умолчанию `Документы\LocalTranscriber`), кнопка **«Открыть папку результатов»** покажет её.
Если текст не распознан (пустой результат), файл не создаётся, чтобы папка не заполнялась
пустыми `.txt`.

Если в редакторе включены таймкоды, при сохранении `.srt`/`.vtt`/`.json` используются исходные
распознанные фрагменты, а не отредактированный текст: правки в редакторе влияют только на `.txt`.

## Настройки

| Параметр | Значение |
|---|---|
| Модель | `small` — быстро, ниже точность; `medium` — баланс (по умолчанию); `large-v3` — максимальная точность, медленно |
| Язык | русский (по умолчанию), автоопределение, английский |
| Потоков CPU | сколько ядер отдать распознаванию (по умолчанию половина логических, но не больше 16) |
| Папка результатов | куда сохранять `.txt` |
| Таймкоды | показывать `[00:12]` в редакторе |

Настройки хранятся в `%APPDATA%\LocalTranscriber\settings.json`.

Ориентиры скорости (замеры на машине 2 × Xeon E5-2696 v3, только CPU, int8, 16 потоков,
`beam_size=1`):

| Модель | Замер | Скорость |
|---|---|---|
| `small` | 68 с речи → 11,3 с | ≈6× быстрее реального времени |
| `medium` | 68 с речи → 22,5 с | ≈3× быстрее реального времени |
| `large-v3` | — | примерно реальное время: час записи ≈ час обработки (оценка) |

Первое распознавание после запуска дольше на 2–4 с — загружается модель (для `medium`
около 3 с). Дальше модель остаётся в памяти.

Больше 16–18 потоков распознавание не ускоряет: на этой машине 36 потоков дают
2,9× вместо 6× из-за конкуренции за кэш процессора (8 потоков — 11,1 с, 16 — 11,3 с,
18 — 11,7 с, 24 — 14,4 с). Поэтому по умолчанию ставится половина логических ядер,
но не более 16.

Точные замеры для вашей машины: `python scripts\benchmark.py "путь\к\записи.mp3" --models small --threads 16`.

## Советы по качеству

- Шумные записи и несколько говорящих — берите `large-v3`.
- Для OCR сканируйте в 300 DPI, без перекоса и с нормальным контрастом; фото — при хорошем освещении.
- PDF с текстовым слоем обрабатывается мгновенно и точно, OCR для них не запускается.
- Если текст распознан неверно, исправьте его в редакторе перед сохранением.

## Офлайн-режим

После загрузки моделей отключите сеть — обработка продолжит работать. Приложение не делает
сетевых запросов во время обработки файлов.

## Обслуживание

- Логи: `%LOCALAPPDATA%\LocalTranscriber\logs\app.log` (ротация 5 × 2 МБ).
- Модели: `%LOCALAPPDATA%\LocalTranscriber\models`. Удалить ненужную модель — просто удалите её каталог.
- Настройки: `%APPDATA%\LocalTranscriber\settings.json`.

## Если что-то не работает

| Симптом | Что делать |
|---|---|
| «В файле нет звуковой дорожки» | у видео нет звука — транскрибировать нечего |
| Долго «Скачивание модели…» | проверьте интернет и место на диске. Загрузку можно отменить и запустить снова: она продолжится с того же места, а после завершения файл проверяется по контрольной сумме |
| «Не удалось загрузить модели OCR» | нужен интернет при первом распознавании изображения; затем всё работает офлайн |
| Не распознаётся русский текст на фото | скан/фото низкого качества или мелкий шрифт — повысьте разрешение |
| Приложение не стартует | проверьте, что Python 3.12+ установлен и `python -m venv` работает; смотрите лог |

### Сборка приложения без Python

```powershell
.\scripts\build_exe.ps1
```

Скрипт собирает `dist\LocalTranscriber\LocalTranscriber.exe` (папку можно переносить
целиком) и сразу проверяет сборку: гоняет `--selftest` на тестовом изображении, PDF и
записи речи. Модели в сборку не входят — они скачиваются при первом запуске.
Размер папки ≈500 МБ (ONNX Runtime, CTranslate2, PyAV, PyMuPDF).

Структура:

```text
src/localtranscriber/
├── app.py                 точка входа, окно
├── audio.py               декодирование через PyAV
├── cancellation.py        токен отмены задания
├── config.py              настройки и пути
├── errors.py              доменные исключения с понятными сообщениями
├── jobs.py                очередь, фоновый поток, пульс прогресса
├── logging_setup.py       логи с ротацией
├── models_setup.py        загрузка моделей с прогрессом и отменой
├── network.py             HTTP-обёртка (системное хранилище сертификатов)
├── pdf.py                 текстовый слой + OCR страниц
├── router.py              тип файла → движок
├── textformat.py          абзацы, srt/vtt/json
├── engines/               whisper_engine.py, ocr_engine.py, base.py
└── ui/                    main_window.py, widgets.py
```

## Ограничения

- Нет диаризации (кто говорил) и потокового распознавания с микрофона.
- Только Windows и только русский/английский интерфейс.
