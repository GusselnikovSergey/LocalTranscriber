## 1. Цель

Получать сборку `.app` для macOS без собственного Mac: порт кода на macOS + сборка
через macOS-раннер GitHub Actions, артефакт скачивается из workflow.

## 2. Границы задачи

### Входит в scope

- Кроссплатформенные каталоги настроек/данных/логов (macOS: `~/Library/…`).
- Кроссплатформенное «Открыть папку результатов» (`os.startfile` → `open`).
- Горячие клавиши и подписи меню с учётом `Command` на macOS.
- `scripts/run.sh` (запуск из исходников) и `scripts/build_mac.sh` (сборка `.app`).
- GitHub Actions workflow: сборка `.app` на `macos-14` (arm64), проверки, артефакт `.zip`.
- Документация: README/HANDOFF — как собрать и как запустить на macOS.

### Не входит в scope

- Подпись Apple Developer ID и нотаризация (нужна платная учётная запись Apple).
- Универсальный бинарник (arm64 + x86_64) — собирается под архитектуру раннера.
- Установщик/`.dmg` (можно добавить отдельной задачей).
- Изменение логики распознавания.

## 3. Функциональные требования

| ID | Требование | Приоритет | Критерий приёмки |
|---|---|---|---|
| FR-01 | На macOS настройки, модели и логи лежат в стандартных каталогах macOS | Must | `appdata_dir()` → `~/Library/Application Support/LocalTranscriber`, `logs_dir()` → `~/Library/Logs/LocalTranscriber` |
| FR-02 | «Открыть папку результатов» работает на macOS | Must | вызывается `open <путь>`; на Windows остаётся `os.startfile` |

## 4. Нефункциональные требования

- Производительность: без изменений (порт не трогает движки).
- Надёжность: при отсутствии Apple Developer ID — ad-hoc подпись, инструкция «правый клик → Открыть».
- Безопасность: никаких секретов в репозитории; внешних сетевых вызовов не добавляем.
- Совместимость: macOS 11+ (arm64); Windows 10/11 — без изменений.
- Наблюдаемость: пути к логам печатаются в «О программе» и лог.

## 5. Допущения

- Сборка на раннере `macos-14` (Apple Silicon, Python 3.13).
- Все зависимости имеют wheel под macOS arm64; проверяется предварительно
  (`pip download --platform macosx_11_0_arm64`).
- Модели не входят в `.app`: скачиваются при первом запуске (как на Windows).

## 8. Тестовая стратегия

- Модульные тесты: пути по платформам (`monkeypatch sys.platform`), открытие папки (подмена `subprocess.Popen`/`os.startfile`), подписи горячих клавиш.
- Интеграционные тесты: полный `pytest` на Windows; в CI — `pytest`, `ruff`, `mypy` на macOS.
- Регрессия: `smoke_check.py`, `gui_smoke.py`, `build_exe.ps1` на Windows.
- Ручные проверки: запуск `.app` на Mac заказчика/знакомого; первый запуск, скачивание модели, распознавание.
- Граничные случаи: отсутствие `HOME`, `xdg-open`/`open` недоступны (ошибка не должна ронять приложение).
