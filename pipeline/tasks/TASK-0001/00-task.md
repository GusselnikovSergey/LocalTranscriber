## Исходная задача / ТЗ

Пользователь: «нужна локальная транскрибация текста».

Уточнения, полученные при приёме задачи (интервью с заказчиком):

1. **Что обрабатываем**: и аудио/видео (речь → текст), и изображения/PDF (OCR). То есть одно приложение на оба сценария.
2. **Формат работы**: простое настольное приложение с окном — перетащил файл → получил текст → скопировал или сохранил. Не CLI, не чат.
3. **Железо**: только CPU, без вычислительной видеокарты. Фактическая конфигурация машины: 2 × Intel Xeon E5-2696 v3 (36 ядер / 72 потока), 64 ГБ RAM, GPU NVIDIA GeForce 210 (непригодна для расчётов). Значит нужен CPU-оптимизированный движок с int8-квантованием и многопоточностью.
4. **Язык**: русский (основной). Допускается автоопределение языка для смешанных записей.
5. **Приватность**: обработка полностью локальная, без отправки файлов в облака. Сеть допустима только для однократной загрузки моделей при первом запуске.

## Первичные заметки координатора

- Проект создаётся с нуля (`greenfield`), каталог `projects/LocalTranscriber` подключён к конвейеру и внесён в `pipeline/projects.json`.
- Проверена техническая выполнимость на текущем окружении (Python 3.14.9, Windows, только CPU):
  - `ctranslate2 4.9.0` — есть колесо `cp314` под win_amd64 → `faster-whisper` работает;
  - `av` — колесо `cp312-abi3`, совместимо с 3.14 → декодирование mp3/m4a/mp4/mkv без внешнего ffmpeg;
  - `onnxruntime 1.31.1`, `opencv-python 5.0`, `numpy 2.5`, `pymupdf 2.0`, `pillow 13` уже установлены;
  - `rapidocr 3.10.0` — чистый Python + onnxruntime, в комплекте есть модель распознавания `cyrillic_PP-OCRv5_rec_mobile` (русский);
  - доступ к huggingface.co и modelscope.cn с машины есть (модели скачиваются однократно).
- Ограничения: нет `ffmpeg` и `tesseract` в системе — приложение не должно от них зависеть.
- GUI: Tkinter (входит в Python) — не требует установки дополнительных GUI-библиотек; drag&drop через `tkinterdnd2` опционально.
