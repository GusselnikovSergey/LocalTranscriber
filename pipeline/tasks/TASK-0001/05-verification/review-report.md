## 3. Потоки, отмена, ресурсы

- **Один worker-поток** (`jobs.py:91`, `daemon=True`), обмен только через `queue.Queue` (`_emit`), UI читает события в `_poll_events` (`after(100)`, до 300 событий за тик). Обращений к Tk из фонового потока нет — проверено по всем вызовам в `_whisper_processor`/`_ocr_engine`/`_build_processor`: только `_post_event` (put в очередь), чтение `self.settings` и `ensure_whisper_model`.
- **Отмена**: `CancelToken` поверх `threading.Event`; проверки в декодере (на каждый кадр), при переборе сегментов whisper, между страницами PDF, перед/после OCR, между чанками загрузки модели. `CancelledError` — наследник `LocalTranscriberError`, ловится отдельно в `jobs._run` и переводит задание в `cancelled`.
- **Кнопки**: `_update_buttons` выключает «Добавить/Очистить/Обработать» и включает «Отмена» на время работы; `JobQueue.clear()` бросает `RuntimeError`, UI дополнительно показывает предупреждение.
- **Закрытие окна**: `_on_close` спрашивает подтверждение, вызывает `cancel()` и `wait(2.0)`, затем `destroy`; поток daemon, поэтому процесс завершится.
- **Ресурсы**: `with av.open(...)`, `with pymupdf.open(...)` (документ закрывается и при `PdfError`), `with Image.open(...)`, `response.close()` в `finally` (`models_setup.py:130-131`), `.part` сохраняется при отмене. Утечек PyMuPDF/PyAV не нашёл.
- **Повторное использование движков**: кэш `_engines` по ключу `(модель, потоки, язык)` и `(ocr, язык)`; сброс при смене настроек. Модель грузится один раз на очередь.
- Замечания: R-05 (гонка `queue_done` → кнопки могут остаться выключенными), R-06 (`probe_duration` и DnD в главном потоке/во время работы), R-09 (латентность отмены), R-15 (смена настроек во время обработки меняет движки на ходу без блокировки).

## 4. Обработка ошибок и безопасность

- «Голых» `except:` нет. Все широкие `except Exception` сопровождаются `# noqa: BLE001`, логированием и трансляцией в доменную ошибку (`audio.py:92`, `ocr_engine.py:133,149`, `jobs.py:147`, `models_setup.py:165`). В `jobs._run` широкий перехват оправдан: очередь не должна падать (FR-10).
- Сообщения пользователю на русском и предметны: «В файле нет звуковой дорожки…», «PDF защищён паролем…», «Не удалось скачать модель. Проверьте интернет и свободное место…», «Библиотека RapidOCR не установлена. Запустите run.ps1…».
- Traceback не показывается: только `_log.exception`, в UI — короткое сообщение (`job_error`, `_set_status`). Исключение — `widgets.py:145` (`IntVar.get()` на нечисловом вводе даёт необработанный `TclError` в колбэке Tk) — R-04.
- **Сеть при обработке**: в `engines`/`audio`/`pdf` запросов нет; `requests` используется только в `models_setup` (список файлов + загрузка). OCR-модель RapidOCR скачивается самим пакетом при первой инициализации — это единственный сетевой путь в обработке, он описан в README и подтверждён офлайн-проверкой после первичной загрузки.
- **Секреты**: отсутствуют; `HF_ENDPOINT` — публичный адрес, токены не используются.
- **Пути**: имена результатов проходят через `safe_filename` (запрещённые символы, пробелы/точки по краям), автосохранение не перезаписывает существующий файл (суффикс `(2)`, `(3)`), пользовательский путь сохранения выбирается только через системный диалог. Path traversal через имя входного файла невозможен (`Path.stem` + фильтрация разделителей).
- **Внешние команды**: не вызываются. `os.startfile` используется только для открытия папки результатов в Проводнике — приемлемо.
- Никакой телеметрии, отправки файлов, `verify=False`, отключения TLS нет; `truststore` лишь подключает системное хранилище сертификатов Windows (обоснованно, зафиксировано в DEV-01/DEV-02).

## 5. Загрузка моделей (`models_setup.py`)

Проверено по пунктам задания:

| Пункт | Оценка |
|---|---|
| Докачка `Range: bytes=N-` | Корректно: `written = temp.stat().st_size`, заголовок только при `written > 0`, режим `ab` для 206 |
| Ответ 200 при существующем `.part` | Корректно: `written = 0`, режим `wb`, повторная загрузка с начала, есть лог |
| Ответ 206 | Принимается без проверки `Content-Range` (целостность затем ловит sha256) |
| Ответ 416 | Обработан только для «файл уже полон»; иначе 3 одинаковые неудачные попытки и общая ошибка (R-13) |
| Проверка размера | Есть: превышение → ошибка сразу, недобор → ошибка и повтор |
| Проверка sha256 | Есть, при несовпадении `.part` удаляется и попытка повторяется (≤3) |
| Отмена | `CancelledError` между чанками, `.part` сохраняется, повторов нет |
| Бесконечные повторы | Отсутствуют: `RETRIES = 3`, `time.sleep` до 6 с с backoff |
| Прогресс | По сумме байтов всех файлов; при ответе 200 учтённый ранее размер `.part` не вычитается → прогресс «перескакивает» и обрезается до 100 % (R-10) |
| Целостность готовой модели | **`model_present()` проверяет только `config.json` и `model.bin`** (`models_setup.py:37-39`), константа `REQUIRED_FILES` не используется → **R-01** |

## 9. Итог

Архитектура соответствует утверждённому плану: UI → JobQueue (один worker-поток, обмен через `queue.Queue`) → router → единый `Processor`-протокол с ленивой инициализацией движков; пути, настройки, логирование, экспорт и доменные ошибки реализованы как в спецификации. Обязательные требования FR-01…FR-15 закрыты, тесты, ruff, mypy и compileall зелёные, сквозные и офлайн-проверки зафиксированы в отчётах. Найденные замечания относятся к устойчивости загрузчика моделей и к граничным сценариям UI, а не к базовой функциональности.

Главный риск — R-01: неполный каталог модели (обрыв или отмена между `model.bin` и `tokenizer.json`) считается готовым, из-за чего приложение уходит в повторяющуюся ошибку без самовосстановления. Плюс расхождение с FR-05 по семантике «Отмена» (R-02) и неполный бенчмарк `medium`/`large-v3` (R-11), из-за которого скорости в README пока остаются оценкой.
