## 1. Что сделано

### D-03 — отмена больше не зависит от блокирующих вызовов движка

Причина задержки: `WhisperModel.transcribe()` до возврата генератора выполняет VAD и
подготовку признаков (на длинной записи — до 3 с под нагрузкой). Всё это время токен не
проверялся, потому что проверки жили в цикле перебора сегментов.

Изменения в `src/localtranscriber/engines/whisper_engine.py`:

- добавлен `call_with_cancel(func, cancel, poll=0.1)` — выполняет блокирующий вызов в
  отдельном daemon-потоке, а основной поток опрашивает токен каждые 100 мс и сразу
  бросает `CancelledError`; исключение из фонового вызова пробрасывается без изменений;
- подготовка распознавания (`model.transcribe(...)`) переведена на `call_with_cancel`;
- загрузка модели (`WhisperModel(...)`) вынесена в фоновый поток `whisper-load` с
  событиями `_load_event` / `_load_error` и блокировкой `_load_lock`: отмена во время
  первой загрузки модели срабатывает за ~0,1 с, а начатая загрузка доводится до конца и
  переиспользуется следующим заданием (повторной загрузки нет). Ранее это был
  единственный документированный случай, когда отмена ждала до конца операции.

### N-01, N-02 — пульс прогресса

`src/localtranscriber/jobs.py`:

- пульс начинает повторять прогресс только после первого реального события
  (`seen_progress`), поэтому при первом запуске сообщение «Скачивание модели N %» и шкала
  загрузки больше не перебиваются заглушкой «Обработка… 0 %» каждые 0,4 с (N-01);
- в `finally` после `stop_heartbeat.set()` добавлен `pulse.join(0.5)`, чтобы устаревшее
  событие `progress` не попадало в очередь после `job_done`/`queue_done` (N-02).

### N-06 — заглушка результата

`src/localtranscriber/ui/main_window.py`:

- заглушки вынесены в константы `PLACEHOLDER_SPEECH` / `PLACEHOLDER_TEXT` / `PLACEHOLDERS`;
- добавлен `_content_text()`: текст редактора без служебной заглушки;
- «Копировать» не копирует заглушку и сообщает «Нет текста для копирования»;
- «Сохранить как…» разрешает сохранение, если в редакторе есть настоящий текст (в том числе
  введённый вручную для файла без распознанного текста), и по-прежнему не сохраняет
  заглушку.

## 4. Отклонения и остаточные риски

- Брошенный фоновый вызов `transcribe()`/загрузки модели досчитывается и выбрасывается:
  на время следующего задания он может кратковременно занимать CPU. Повторной загрузки
  модели не происходит — результат потока кэшируется в движке.
- Брошенная генерация `faster_whisper` не отменяется на уровне C++ (API не даёт),
  но её результат уже не влияет на задание.
- `probe_duration` при добавлении файлов по-прежнему работает в главном потоке (R-06,
  для локальных файлов — единицы мс), оценка времени обработки (R-09) не реализована —
  перенесено в остаточные работы, на FR не влияет.
- Замеры `medium`/`large-v3` не снимались (медленный канал), в README честно оценка.
