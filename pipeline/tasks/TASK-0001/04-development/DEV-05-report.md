# Отчёт DEV-05: первый запуск (модели), бенчмарк, README, офлайн-проверка

## Что сделано

- `models_setup.py` — собственный загрузчик моделей вместо `huggingface_hub`:
  - список файлов и размеры берутся из API Hugging Face (`?blobs=true`), включая `sha256` LFS-объектов;
  - скачивание потоковое, в `.part`-файл, с докачкой через заголовок `Range: bytes=N-`;
  - незавершённые данные **сохраняются**: после обрыва связи, таймаута или отмены повторный
    запуск продолжает загрузку с того же места;
  - если сервер игнорирует `Range` (код 200), файл аккуратно перекачивается заново;
  - по завершении проверяется `sha256`; при несовпадении файл удаляется и загрузка повторяется
    (до 3 попыток), поэтому повреждённая модель не попадёт в кэш;
  - прогресс считается по байтам всех файлов модели, поддерживается отмена;
  - понятная ошибка при отсутствии сети: «Проверьте интернет и свободное место на диске:
    следующий запуск продолжит загрузку с того же места».
- `config.py` — `default_cpu_threads()` теперь «половина логических ядер, но не больше 16»:
  замеры показали, что 36 потоков на 2 × Xeon E5-2696 v3 вдвое медленнее 16 (конкуренция за кэш).
- `scripts/benchmark.py` — замер RTF на файле для выбранных моделей и числа потоков.
- `scripts/smoke_check.py` — сквозная проверка OCR, PDF и речи без GUI.
- `scripts/gui_smoke.py` — проверка окна: очередь, обработка, автосохранение; добавлены
  `--audio` (сквозная проверка речи через UI), `--language`, `--model` и ожидание обработки
  событий после завершения очереди.
- `tests/test_models_setup.py` — 12 тестов загрузчика: докачка с `Range`, перезапуск при
  игнорировании `Range`, повторы при неполной загрузке, сохранение `.part` при отмене,
  отказ при лишних байтах, проверка `sha256` (успех и повреждение), перезапуск после `416`,
  обёртка сетевой ошибки в `ModelUnavailableError`, `model_present` по всем обязательным
  файлам, докачка только недостающих файлов и понятная ошибка при неполной модели.
- `tests/test_whisper_engine.py` — тесты `iter_with_cancel`: сегменты проходят, отмена не ждёт
  медленный сегмент (проверка FR-05), ошибки движка пробрасываются.
- `requirements.txt` — версии зависимостей зафиксированы (`==`) по проверенному набору;
  инструменты разработки вынесены в `requirements-dev.txt`.
- `README.md` — установка, первый запуск, офлайн-режим, выбор модели, советы по качеству,
  troubleshooting, измеренные скорости, семантика отмены и автосохранения.
- `testdata/` — генератор синтетических файлов (`make_testdata.py`): русское изображение,
  PDF с текстовым слоем, скан-PDF, тон 3 с; английская речь на 9,4 с и 68 с (SAPI).

(36 ядер / 72 потока), 64 ГБ RAM. Внешние `ffmpeg` и `tesseract` не используются.

Автосохранение: в `testdata/output` появились `sample (2).txt`, `digital (2).txt`,
`scanned (2).txt`, `speech_en_long.txt` (1041 символ) — по одному файлу на задание,
как требует FR-10; пустые результаты не сохраняются.

Отмена (методика тестировщика, `speech_en_long.wav`, отмена через 0,05–3 с):

```text
через движок: задержки 0.00–0.35 с, медиана 0.11 с, больше 3 с: 0 из 8
через JobQueue (движок прогрет): 0.02–0.09 с, 0 из 5
```

Как это сделано: `beam_size` снижен до 1, а сегменты вытягиваются отдельным потоком
(`iter_with_cancel`), поэтому отмена не ждёт, пока модель досчитает текущий сегмент:
основной поток проверяет токен каждые 0,1 с и сразу поднимает `CancelledError`, а
незавершённый сегмент досчитывается в фоне и выбрасывается. Единственное исключение —
отмена во время самой первой загрузки модели (конструктор `ctranslate2` не прерывается):
латентность равна времени загрузки, на `small` это 2,7 с (≤3 с), на диске с холодным
кэшем может быть больше. Это ограничение зафиксировано в README.

## Бенчмарк

Файл: `testdata/generated/speech_en_long.wav`, английская речь 68,1 с, `small`, int8,
`beam_size=1`, VAD silero.

| Потоков CPU | Время обработки | RTF | Быстрее реального времени |
|---|---|---|---|
| 8 | 11,1 с | 0,16 | 6,1× |
| 16 | 11,3 с | 0,17 | 6,0× |
| 18 | 11,7 с | 0,17 | 5,8× |
| 24 | 14,4 с | 0,21 | 4,7× |
| 36 | 23,3 с | 0,34 | 2,9× |

Вывод: производительность выходит на плато при 8–18 потоках, дальше падает.
Поэтому `16` — разумный дефолт, а не «половина всех потоков».

Модель `medium` в этой сессии не бенчмаркалась: канал до CDN в момент проверки отдавал
~0,2 МБ/с, а файл весит 1,5 ГБ (≈1,5 часа). Загрузчик при этом проверен на `small` (докачка,
`sha256`), а движок и формат модели те же. В README скорость `medium` помечена как оценка.
Частично скачанный `model.bin.part` оставлен в кэше — приложение продолжит загрузку
с того же места при первом аудиофайле.

Проверить `medium` на своей машине можно так:

```powershell
.\.venv\Scripts\python.exe scripts\benchmark.py "путь\к\записи.mp3" --models medium --threads 16 --language ru
```

## Отклонения от задания

- **R-07 (диалог загрузки моделей).** Загрузка показывается в строке состояния главного окна,
  а не в отдельном диалоге; отдельной кнопки «Повторить» нет — повторный запуск выполняется
  кнопкой «Обработать», а `.part` докачивается с того же места. Причина: одно окно и один
  индикатор прогресса по требованию ТЗ; отдельный диалог добавил бы второй цикл событий.
  Проверка размеров уже скачанных файлов добавлена (`ensure_whisper_model` сверяет размер
  каждого файла с API и докачивает только несовпадающие).
- В плане для Whisper упоминался `huggingface_hub.snapshot_download`. Отказались по итогам
  живой проверки: CDN обрывает соединения (`Read timed out`) и не поддерживает возобновление
  средствами библиотеки, а из-за TLS-инспекции антивируса обычный `requests` падал с
  `CERTIFICATE_VERIFY_FAILED`. Свой загрузчик с системным хранилищем сертификатов
  (`truststore`), `Range`-докачкой и проверкой `sha256` оказался устойчивее.
- OCR-модель RapidOCR скачивается самим пакетом при первой инициализации в
  `%LOCALAPPDATA%\LocalTranscriber\models\ocr`; отдельный загрузчик для неё не нужен.
- `large-v3` (3 ГБ) не скачивался: канал ~1–2 МБ/с, а поведение движка то же, что у `small`
  и `medium`. Оценка в README дана по числу параметров и помечена как ориентир.

Скрипт-проверка запрещал любые `socket.connect` и запускал OCR изображения, скан-PDF и
распознавание речи на уже скачанных моделях:

```text
[OCR] 3.7 с -> Локальная транскрибация текста
[PDF scan] 2.7 с -> Локальная транскрибация текста
[Речь] 4.3 с -> Local transcription test, the quick brown fox jumps over the lazy dog, ...

Офлайн-проверка: OK
```

FR-15 выполнен: после загрузки моделей обработка не делает сетевых запросов.

## Риски

- Сеть до CDN Hugging Face нестабильна: большие модели (`medium`, `large-v3`) качаются
  десятки минут. Докачка и проверка `sha256` снимают риск повреждённого кэша.
- Скорость зависит от числа физических ядер; на ноутбуках RTF будет выше.
- Качество распознавания синтетической речи SAPI не равно качеству на реальных записях —
  финальная проверка на файлах заказчика выполняется на приёмке.
