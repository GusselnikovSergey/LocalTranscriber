# Ручной тест LocalTranscriber

Короткий чек-лист для проверки приложения руками. Отмечайте пункты и пишите, что
получилось не так — по каждому пункту есть ожидаемое поведение.

> На этой машине модели уже скачаны (`small` и `medium` в
> `%LOCALAPPDATA%\LocalTranscriber\models`), поэтому раздел 4 (скачивание моделей)
> можно пропустить. Он нужен, если проверять на другом компьютере или после удаления
> папки моделей.

## 1. Запуск

**Вариант А — готовая сборка (ничего устанавливать не нужно):**

```text
dist\LocalTranscriber\LocalTranscriber.exe
```

**Вариант Б — из исходников:**

```powershell
cd "C:\Users\Сергей\Documents\Проект по умолчанию\projects\LocalTranscriber"
.\run.ps1
```

Ожидаемо: открывается окно «LocalTranscriber 1.x — локальная транскрибация» примерно за 2–5 с.
Если окно не появилось — смотрите `%LOCALAPPDATA%\LocalTranscriber\logs\app.log`
(и `crash.log`, если он есть).

## 2. Аудио и видео

| # | Что сделать | Ожидаемо |
|---|---|---|
| 2.1 | Перетащить в окно mp3/wav/m4a (1–2 мин русской речи) | файл появляется в списке, видна длительность |
| 2.2 | Нажать «Обработать» | внизу идёт процент, в списке статус «Обработка…», справа появляется текст |
| 2.3 | Дождаться конца | статус «Готово», текст разбит на абзацы, `.txt` сохранён в `Документы\LocalTranscriber` |
| 2.4 | Выбрать файл, нажать «Копировать» | текст в буфере обмена |
| 2.5 | «Сохранить как…» → `.srt`, затем `.vtt`, затем `.json` | три файла с таймкодами; `.srt` открывается в проигрывателе |
| 2.6 | Включить «Таймкоды» в настройках | в редакторе появляются метки `[00:12]` |
| 2.7 | Добавить видео mp4/mkv со звуком | распознаётся так же, как аудио |
| 2.8 | Добавить видео без звуковой дорожки | понятная ошибка «В файле нет звуковой дорожки», очередь продолжается |
| 2.9 | Запустить второй файл и нажать «Отмена» | текущий файл «Отменено» за 1–2 с, остальные остаются «В очереди»; «Обработать» продолжает с них |

## 3. Изображения и PDF

| # | Что сделать | Ожидаемо |
|---|---|---|
| 3.1 | Перетащить фото документа (jpg/png) | текст появляется в порядке строк, русский распознан |
| 3.2 | Перетащить PDF с текстовым слоем | обрабатывается мгновенно (~0,1 с), текст точный |
| 3.3 | Перетащить скан-PDF | распознаётся через OCR, страницы помечены `--- стр. N ---` |
| 3.4 | Попробовать плохой скан/фото (мелкий шрифт, перекос) | текст может быть с ошибками — это ожидаемо; проверьте, что приложение не падает |
| 3.5 | PDF с паролем | понятное сообщение «PDF защищён паролем» |

## 4. Первый запуск и модели (если модели ещё не скачаны)

| # | Что сделать | Ожидаемо |
|---|---|---|
| 4.1 | Первый аудиофайл на чистом кэше | «Скачивание модели…» с процентами, шкала растёт и не скачет к нулю |
| 4.2 | Во время скачивания нажать «Отмена» | отмена за 1–2 с; при следующем запуске скачивание продолжается с того же места |
| 4.3 | Отключить интернет и обработать файл (модель уже скачана) | всё работает, сетевых ошибок нет |
| 4.4 | Отключить интернет, удалить папку модели, нажать «Обработать» | понятное сообщение про интернет и повтор, без технического текста исключения |

## 5. Настройки и мелочи

| # | Что сделать | Ожидаемо |
|---|---|---|
| 5.1 | Сменить модель на `small`, язык на «Английский», потоки на 8 | следующие файлы обрабатываются с новыми настройками; после перезапуска настройки сохранились |
| 5.2 | Ввести в «Потоков CPU» буквы и нажать «Сохранить» | сообщение об ошибке, диалог не падает |
| 5.3 | Обработать файл без речи (тишина/тон) | «Речь не обнаружена», пустой `.txt` не создаётся, «Копировать» не копирует заглушку |
| 5.4 | «Открыть папку результатов» | открывается `Документы\LocalTranscriber` с сохранёнными `.txt` |
| 5.5 | Закрыть окно во время обработки | вопрос «Остановить обработку и закрыть?», приложение закрывается за 1–2 с |

## 6. Куда смотреть при проблеме

- Лог: `%LOCALAPPDATA%\LocalTranscriber\logs\app.log` (ротация 5 × 2 МБ).
- Настройки: `%APPDATA%\LocalTranscriber\settings.json`.
- Модели: `%LOCALAPPDATA%\LocalTranscriber\models` (можно удалить каталог модели — скачается снова).
- Результаты: `Документы\LocalTranscriber`.

## 7. Что прислать в ответ

1. Какие пункты прошли, какие нет (номер + что именно произошло).
2. Для сбоя — файл `app.log` и по возможности сам входной файл.
3. Замеры, если важны: длительность записи и время обработки (видно в статусе и логе).
